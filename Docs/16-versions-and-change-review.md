# النسخ المحفوظة ومراجعة تغيير فرع

المسار المحلي العام: ادخل `/planner`، احسب الخطة، افتح توزيع المنافذ تحت البديل المختار، ثم نزّل «لقطة للمراجعة». في `/review` ارفع اللقطة أو استخدم المثال، أدخل VLAN ومنافذها، واختر السويتش ثم اعرض الفرق. لا تحتاج الشاشة العامة لحساب أو قاعدة بيانات أو مزود AI.

- مدخل المراجعة لقطة `nettopo-branch-snapshot` بالإصدار 1 (توصيلات وواجهات وVLANs وعناوين وتوزيع منافذ ووسوم الربط). تقرير JSON العادي من المخطط مختلف؛ استخدم زر «تنزيل لقطة للمراجعة». الحد 48 KiB للملف من الواجهة، و64 KiB لطلب API بما فيه وصف التغيير.
- `POST /api/v1/branch-changes` يقبل `{snapshot,segment}`. في `segment`: `id,label,vlanId,endpointAddresses,accessPorts,switchId`. يحافظ على تخصيص العناوين والمنافذ الحالي، ويضيف VLAN عبر مسار الربط للراوتر. تداخل العناوين أو إعادة استخدام منفذ أو VLAN يمنع التغيير. معلومات الربط غير الكافية تنتج `insufficient-evidence`.
- التقرير يربط النتيجة ببصمة SHA-256 للّقطة المحلّلة. إذا أمكن توليد مرشح، يتضمن فرقًا وبيانات تراجع: إزالة تخصيصات المنافذ الجديدة وإرجاع وسوم الربط وإزالة الشبكة المضافة. يمكن استخدام `candidate` كلقطة لاحقة بعد حفظه منفصلًا. حالة السلوك والسياسات تظل «غير متحقق منها» حتى يوجد دليل آخر.

المسار المحفوظ: جهّز PostgreSQL محلي أو مخصص لهذا التطبيق، واضبط `DATABASE_URL` و`DIRECT_URL` ومفاتيح Clerk. شغّل `npx prisma migrate deploy` **على قاعدة البيانات المخصصة فقط**. افتح `/designs` بحسابك. احسب الخطة، سمّها واحفظها. تقدر تفتح آخر 100 نسخة من القائمة، وتفتح الأقدم عبر API. لحفظ نسخة جديدة افتح أحدث نسخة ثم عدّل واحسب الخطة مرة ثانية.

| العملية | العقد |
| --- | --- |
| جلب التصميمات | GET /api/v1/branch-designs (آخر 50 تصميمًا للحساب) |
| حفظ أول نسخة | POST /api/v1/branch-designs مع `{name,input}` |
| فتح أحدث نسخة أو نسخة محددة | GET /api/v1/branch-designs/{id} أو `?revision=1`؛ يعيد آخر 100 رقم نسخة في القائمة ويمكن فتح رقم أقدم عبر API |
| حفظ نسخة لاحقة | POST /api/v1/branch-designs/{id} مع `{expectedHead,input}`؛ عند سباق حفظ، كاتب واحد ينجح والآخر يأخذ 409 |

المالك يؤخذ من جلسة Clerk ويطبّق على كل قراءة وكتابة. يَحسب السيرفر الخطة ويحفظ الناتج. كل نسخة تظل ثابتة، والعزل يطبّق على الحساب الفردي. المراجعة تخص إضافة VLAN.

من `/review` افتح «استيراد إعدادات Cisco». الاستيراد يدعم راوتر وسويتش بينهما وصلة مباشرة بنمط Router-on-a-stick. يحتاج ملفي running-config نصيين، اسمي طرفي الوصلة بالكامل، ومجال IPv4 المخصص. حد كل ملف 96 KiB. الملفان يُقرآن داخل المتصفح، ويستقبل الخادم اللقطة المنظّمة عند طلب حساب الفرق.

- يلزم تعيين `switchport mode trunk` وقائمة allowed VLAN صريحة بأرقام ونطاقات، وبوابة IPv4 واحدة لكل واجهة فرعية مفعّلة تستخدم `encapsulation dot1Q`. الإعدادات المركبة مثل EtherChannel وnative VLAN غير الافتراضي خارج نطاق الاستيراد.
- تدخل المنافذ المعيّنة إلى الشبكات المستوردة في المقارنة. المنافذ الاحتياطية يحددها المستخدم بالاسم وتحتاج `shutdown` وغياب تعيين VLAN. احتفظ بمجال عناوين مخصص ومؤكد خارج الأداة.
- يعرض التقرير السماح بوسوم VLAN على مسار الربط قبل وبعد، للشبكات المعينة إلى منافذ. الفحص يصف نموذج الإعدادات. تظل حركة البيانات وحالة الوصلات وسياسات الوصول بحاجة إلى دليل تشغيل.

مرجع تكوين الوصلة والواجهات الفرعية [دليل Cisco للتوجيه بين VLANs باستخدام راوتر خارجي](https://www.cisco.com/c/en/us/support/docs/lan-switching/inter-vlan-routing/14976-50.html).

لتشغيل اختبار النسخ الفعلي مع الاختبارات العادية: فعّل `NETTOPO_TEST_DATABASE_URL` لقاعدة **محلية مؤقتة مطبّق عليها migrations** ثم `npm test`؛ يعزل الاختبار حسابين وهميين، ويتحقق من نسخة سابقة وحفظين متزامنين. حسابات الإنتاج غير لازمة للاختبار.
