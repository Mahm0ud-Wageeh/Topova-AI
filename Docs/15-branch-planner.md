# تشغيل مخطط الفرع

أول جزء منفذ من خريطة الطريق: نموذج أجهزة ومنافذ ووصلات لفرع صغير، تخصيص IPv4، ومقارنة بديلين في واجهة عربية. من جذر المستودع شغّل `npm run dev` بالإعدادات العامة للتطبيق، ثم افتح `http://localhost:3000/planner`.

- الواجهة React في `frontend/components/planner/branch-planner.tsx`. النموذج يفتح بمثال قابل للتعديل ويصدر JSON وحزمة Cisco للبديل المختار.
- الخادم Node.js مستقل في `backend`. يقبل `POST /api/v1/branch-plans` الإصدار `1` ومجال `parentCidr` وعدد `portsPerSwitch` من 24 أو 48 وحتى 12 عنصرًا في `segments`. حقل `portReservePercent` اختياري من 0 إلى 100 والقيمة الافتراضية 20. كل عنصر يحمل `id` و`label` و`vlanId` و`endpointAddresses` و`accessPorts` و`minimumPrefix` اختياريًا.
- لا يتصل الحساب بقاعدة البيانات أو مزود AI، ولا يحفظ الطلب. صفحتا `/planner` و`/review` لا تستدعيان Clerk. المسارات التي تفتح أو تحفظ المشاريع تبقى خاصة وتحتاج إعداد Clerk وPostgres. حد الطلب 12 KiB.
- الرد يحمل التخصيص، مجال الأجهزة الممكن بعد حجز البوابة، والعناوين الحرة، وبديلًا بسويتش وبديلًا بسويتشين. البديل غير القابل للتنفيذ يظهر عدد المنافذ الناقصة. لكل بديل ممكن نموذج topology وتخصيص منافذ. JSON تالف: 400، تجاوز الحجم: 413، نوع محتوى خاطئ: 415، المدخل غير المقبول أو نفاد مجال العناوين: 422.

النطاق الحالي راوتر واحد وسويتش واحد أو سويتشان. يختار المحرك البديل الأقل في عدد الأجهزة إذا حقق الاحتياطي المطلوب. يقبل `POST /api/v1/cisco-exports` نفس المدخل مع `alternativeId` و`profile`، ويعيد ملف ZIP للتجربة في المعمل.
