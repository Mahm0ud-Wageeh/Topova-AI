# محرك تصميم الشبكات

## خط المعالجة

1. normalize: وحد الوحدات والأسماء والصيغ وحافظ على الأصل ودلالة القيمة (مطلوبة / مفضلة / مفترضة / مجهولة).
2. allocate: اختر topology profile من القيود، ثبّت الأجهزة والواجهات، احسب السعة، خصّص العناوين واربط مصادر كل قرار. في Brownfield ثبّت الأجزاء الخارجة عن نطاق التغيير.
3. validate: فحص النموذج ومصفوفة الإمكانات والسياسات. قدم status مستقل لكل اختبار.
4. compare: اعرض graph diff وIP/VLAN/Interface diff، ثم نتيجة أثر من المحلل إن كان يغطي المسار.
5. render: حول النموذج الذي اجتاز البوابات إلى ملفات دعم مثبتة للإصدار المحدد؛ renderer لا يخترع حقيقة. التصدير يحمل نفس revision.

| Rule ID | ماذا يفحص | نتيجة أو حد |
| --- | --- | --- |
| NET-01 | IDs وreferences والوصلات المتكررة والمنافذ الحرة والأدوار المسموحة | نرفض duplicate/dangling أو التخصيص غير الممكن؛ التوافر الكهربائي أو الفيزيائي يحتاج بيانات |
| IP-01 | IPv4 صالح وCIDR aligned، subnet ضمن parent بلا overlap أو تجاوز | VLSM أكبر متطلب أولًا، tie-break حسب VLAN ID. reservations سياسة مدخلة. capacities تحسب gateway وstatic/growth. طبّق الفحص على baseline والأجزاء الجديدة حسب نطاقها |
| IP-02 | عنوان فريد في نطاقه، gateway في subnet، DHCP لا يتداخل مع الحجز | لا تُحتسب network/broadcast كعناوين مضيف في LAN؛ توفير قدر كاف من عناوين DHCP |
| VLAN-01 | VLAN IDs صحيحة حسب profile؛ access membership وtagging متسقان عبر trunk | explicit mapping؛ إذا كان الجار أو trunk غير مستورد، unknown لذلك الجزء |
| RT-01 | مراجع الـnext hop ومداخل route أو gateway في النطاق المدعوم | single-router connected routing هو الخط الأساس؛ أي بروتوكول غير مثبت يظهر unsupported. توسعة OSPF في profile مستقل |
| POL-01 | هل المرور المطلوب مسموح/محجوب حسب نموذج وأدلة تدعم directional reachability؟ | مُحلل موثوق أو معمل؛ الرسم نفسه لا يثبت ACL/NAT أو forwarding |
| CHG-01 | لا حذف/تبديل خارج نطاق طلب التغيير، وتصنيف الاختلافات المؤثرة | يعرض ما يتعذر حصر أثره بسبب نقص البيانات |

**حالات النتيجة:** pass، fail، unknown (بيانات ناقصة)، unsupported (الميزة خارج التغطية)، not_run. التنبيه أو الملاحظة severity وليس حالة مستقلة. كل result يحدد ruleId، objects، evidence، scope، سببًا وتوصية. pass يعني فقط داخل النطاق المدعوم. report يميز فحص بيانات/سلوك نمذجي/تجربة معملية؛ لا تستخدم telemetry labels.

**VLSM:** استخدم دوال رقمية ترفض الصيغ غير الصحيحة وتمنع overflow، والـallocator يرجع النتيجة keyed by segmentId. في شبكة قائمة، التخصيص يحترم جميع الشبكات المتداخلة مع pool المثبت. عند نفاد المساحة أرجع مقدار النقص وخيارات إعادة تصميم؛ لا تغيّر parent بصمت. الارتباط بالـVRF مدعوم في الهوية من البداية ويمكن قصر فحص v1 على VRF افتراضي.

**المقارنة:** استخدم hard constraints للتصفية، ثم مقارنة عدد الأجهزة والمنافذ الحرة وعمليات التغيير ومتطلبات السياسة والأدلة. مدى الثقة يُعرض لكل عامل؛ لا تحول unknown إلى قيمة رقمية صفر في الترتيب.

**التراجع:** استند للـbaseline الذي قورن فعليًا، واذكر الشروط المسبقة والحالة القابلة للاسترجاع وفحص ما بعد التراجع. إذا كان عكس خطوة غير معروف آليًا، اجعلها خطوة مراجعة يدوية واضحة بدل إنشاء أمر تخميني.
