# التحقق والتقييم

ابدأ بـ[الحالة الاصطناعية المرجعية](fixtures/branch-01.json). القيم فيها متوقعة لما ينبغي أن يفعله المنتج؛ ليست نتيجة تشغيل مختبر. اجعل fixtures تغطي AR/EN، غياب حقل هام، تداخل CIDR، حجز gateway، نفاد منفذ، استيراد جزئي، وفرق يؤثر في سياسة موجودة.

| الطبقة | دليل الخروج |
| --- | --- |
| Unit / property | تخصيص ضمن pool، alignment، صفر overlap، capacity شاملة الحجوزات، IDs مستقرة، إدخال غير صالح يرفض. توليد randomized cases بseed قابل للتكرار |
| Contracts / adapter | حالات import وexport وAPI، parser coverage وprovenance، JSON round trip، ملفات unsupported لا تختفي |
| Integration | حفظ/فتح بمستخدمين مختلفين داخل وخارج Workspace؛ مراجعة stale ترفض؛ ترحيل قاعدة فارغة؛ cancel/retry للـworker؛ اختبار عدم egress عند تعطيل المزود |
| E2E | كلا المسارين من الإنشاء إلى حزمة، provider غائب، baseline ناقصة، وتغيير لا يمر؛ desktop وقراءة RTL على شاشات أصغر |
| Lab | طبق مثال Cisco يدويًا داخل مختبر؛ سجل المنصات والإصدارات والمنافذ، نتائج اتصال مسموح/ممنوع، أثر الفرق، والاسترجاع. اربط الأدلة ببصمة النسخة |
| Pilot | نفّذ نفس السيناريو بالطريقة الحالية وباستخدام المنتج مع مراجعين مستقلين؛ سجل الوقت للمخرج المقبول والأخطاء التي لم تُكتشف |

## سيناريو مرجعي

- Greenfield: موقع واحد، 12 مستخدمًا و4 خوادم وواجهة إدارة واحدة، parent `10.50.0.0/24`. سياسة fixture الصريحة تحجز block إدارة بحجم 8 عناوين؛ يعرض المنتج السياسة للمستخدم ضمن الافتراضات. قارن سويتش 24 منفذًا مع خيار سويتشين مدعومين. لا تدّعِ redundancy من استخدام سويتشين إذا بقي router واحد.
- Brownfield: ثبّت خطة الحالة كـbaseline. أضف 4 أجهزة ضيوف وVLAN 40؛ يُبقي المرشح الشبكات والمنافذ الموجودة دون تغيير إلا لتحقيق الطلب. guest → management ممنوع كـassertion مدخل، وstaff → خادم معتمد يستمر. في نموذج غير مكتمل يجب أن تظهر policy كـunknown أو unsupported.
- سلبية: parent `10.50.0.0/28` لا يستوعب المجموع. ودوس restart أو refresh لا يفقد المسودة أو يعيد تعريف baseline.
- Acceptance: تأكيد العناوين والـports أولًا، ثم فحص توصيل/سياسة بنطاق موثق في المختبر. ابدأ اختبار المنع بإثبات أن الاتصال المرجعي المتوقع يعمل قبل التغيير وعلى endpoint صحيح؛ timeout وحده لا يثبت أن ACL سبب المنع. نفّذ التراجع داخل المعمل وأعد فحص السلوك المرجعي.

## قياس الفرضيات

هدف داخلي أولي: صفر مخالفات invariant على fixtures المؤيدة، وصفر عبور بيانات بين Workspaces في الاختبارات، و100% من الحالات الحرجة المعروفة إما تُكتشف أو يُعلن بوضوح أنها غير مغطاة. سجّل precision/recall لاستخراج الحقول، مصفوفة false pass/false fail/unknown لفحص التصميم، ووقت الوصول للمخرج + عدد تعديلات المهندس. حالة unknown تبقى في المقام عند قياس التغطية. لتجربة المقارنة اقترح 20 طلبًا موزعة على اللغة والمسار وحالات الفشل؛ قسّم التطوير عن التقييم واعرض قيم العينة بدل نسب تسويقية عامة. لا تدّعِ تحسن الوقت قبل قياسه.

بوابة pilot: تشغيل قابل للتكرار، حالة ذهبية لكلا المسارين بأدلة مرتبطة بالنسخة، تقرير حالات غير مدعومة، استرجاع backup مثبت، ومراجع يوقّع على ما تحقق في النطاق. هذا باب تجربة الشركة، وليس اعتمادًا عامًا للشبكات.
